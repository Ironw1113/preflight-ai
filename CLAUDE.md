# Preflight AI — project context

## What this is
Preflight AI is **the pre-approval layer for AI spend**: describe an AI task, workflow, or coding job, and get variance-honest cost forecasts (P50/P90/blowout) across all major AI platforms *before* any money is spent. Positioning and strategy live in `../Preflight-AI-Business-Plan-v2.docx`. Category framing: we **predict and pre-approve** spend; observability tools (Helicone, Langfuse) only watch it after the fact. The four-stage product loop is Predict → Approve → Enforce → Learn.

## Non-negotiable product principles
1. **Variance honesty is the brand.** Never present a single point estimate. Every cost surfaces P50 / P90 / blowout, with risk tiers per task type (see `RISK_TIERS` in the estimator). CFO guidance: budget to P90, cap at blowout.
2. **Graceful degradation.** Everything must work without an API key (heuristic fallbacks). `ANTHROPIC_API_KEY` upgrades classification to Claude; its absence must never break anything.
3. **Estimates are labeled heuristic** until calibrated against real usage. The calibration dataset (predicted vs actual) is the long-term moat.

## Architecture
- `server/` — Node/Express API.
  - `lib/estimator.js` — all estimation logic: task profiles, token math, `RISK_TIERS`/`TASK_RISK` variance system, `modelResults()` shared pricing core, `estimate()`, `estimateWorkflow()` (context accumulation: each step's input carries all previous outputs), `estimateCode()` (agent-loop multipliers, now **async**), `estimateCodingTools()` (flat-seat subscriptions with quota/seat math). `estimateCode()` takes either an explicit `taskKind` (skips classification, used by tests/API consumers who already know it) or a `description`, classified into a `taskKind` by `classifyCodeTaskKind()` — same Claude-tool-call-with-heuristic-fallback pattern as `classifyTask()`, just a different category set (`CODE_TASKS`: bugfix/feature/refactor/tests/review/greenfield) and its own keyword table (`CODE_TASK_KEYWORDS`).
  - `lib/approvals.js`, `lib/signoffDoc.js`, `lib/guardrailConfig.js` — the "Approve"/"Enforce" stages (budget requests with audit trail + printable sign-off; LiteLLM/Portkey/webhook guardrail config from an approved request). **Built and tested, but not mounted in `index.js`** as of 2026-07-28 — paused pending a decision on how to scale the SQLite-backed persistence (`node:sqlite`, `DatabaseSync`, hence the Node >=22.5 requirement in `render.yaml`/`engines.node` even though nothing currently uses it live). Their `test/*.test.js` files still run and pass since they exercise the lib functions directly, not via HTTP. To re-enable: re-add the requires and routes removed from `index.js` (see the comment block at its top) and the `ApprovalRequestForm`/`ApprovalsMode` UI (see git history around the "remove approvals" commit). See ROADMAP.md.
  - `lib/fileExtract.js` — server-side text extraction for the file-upload estimators (multer memoryStorage — files are never written to disk). Plain text/code pass through directly; PDF via `pdf-parse`, DOCX via `mammoth`. XLSX/XLS are handled by hand (unzip with `fflate` + regex over the worksheet/sharedStrings XML for `<t>` text nodes) rather than a spreadsheet library: the maintained npm option (`xlsx`/SheetJS) has unpatched high-severity advisories, `exceljs` drags in a vulnerable writer-only dependency chain we'd never exercise, and `read-excel-file@9.3.4` has a reproducible crash on this Node version (`readFiles(...).then is not a function` — confirmed with both tiny and 200-row fixtures, so it's not a size edge case). Since we only need text for word-counting/classification (not full cell typing), the regex approach avoids all three.
    - `extractText()` (`POST /api/extract-text`, single file, Single Task estimator): `wordCount()` overrides the manual `avgInputWords` guess; a bounded snippet (`MAX_SNIPPET_CHARS`) flows into `classifyTask()`.
    - `extractProjectText()` (`POST /api/extract-project`, multiple files/a folder, Code estimator): aggregates word counts across many files and never throws for one bad file — junk paths (`SKIP_PATH_SEGMENTS`: node_modules, .git, dist, build, ...) and unsupported extensions are silently skipped, per-file extraction errors are recorded but don't fail the batch. **Important gotcha**: relative paths (needed to recognize `node_modules/...`) can't ride on each file's own multipart filename — the multipart/form-data spec reduces any filename containing `/` to its basename (confirmed with curl and Node's own `fetch`/`FormData`, so real browsers do the same). The client instead sends a companion `paths` field (JSON array, same order as `files`) that `index.js`'s route zips back onto each file before calling `extractProjectText()`. If you ever touch this flow, keep that pairing intact.
  - `data/models.json` — verified per-1M-token pricing + heuristic quality/speed scores. Update prices here only, from official provider pages.
  - `test/*.test.js` — run with `npm test` (globs all `test/*.test.js`). Tests delete `ANTHROPIC_API_KEY` to force deterministic heuristic paths; `approvals.test.js` uses `resetDbForTests(":memory:")` for isolation; `fileExtract.test.js` uses real fixtures in `test/fixtures/` (a hand-built PDF/DOCX/XLSX, not mocks — regenerate via `textutil`/`cupsfilter` on macOS if they ever need to change). Keep all tests passing; add tests for any estimator/approvals/extraction change.
- `client/` — React + Vite. `src/Landing.jsx` is the marketing homepage (hero, variance explainer, Predict→Approve→Enforce→Learn, features, pricing, footer) plus the shared sticky `SiteNav`; `src/App.jsx` holds the estimator app with three mode tabs (Single task / Multi-step workflow / Code estimator). Routing is dependency-free hash routing in App's default export: `#/app` → estimator, anything else → landing. The landing page's "Approval workflow" feature card is flagged `soon: true` — the UI for it (formerly `ApprovalRequestForm`/`ApprovalsMode`) was removed when the backend routes were paused (see `lib/approvals.js` note above); bring both back together. `CodeMode` has no task-kind dropdown — it's a free-text description (like `SingleMode`), classified server-side — plus `ProjectUpload`, which offers both a multi-file picker and a folder picker (`webkitdirectory`) and posts to `/api/extract-project` with the `paths` companion field described above. Dark theme + Inter font in `src/styles.css` (landing styles prefixed: `.hero`, `.sitenav`, `.tier-card`, etc.). Dev server proxies `/api` to :3001.
- Deployed on Render (`render.yaml`).

## Conventions
- Plain CommonJS on the server, no TypeScript, no new dependencies without good reason.
- API responses stay backward compatible: keep `monthlyCost.{low,mid,high}` alongside `scenarios.{p50,p90,blowout}`.
- Quality scores are 0–100 heuristic seeds; don't present them as benchmark results.
